ADR-002: Comunicação IPC via HTTP

Aceito • 2026-05-16

Contexto

O frontend (webview) e o backend (Java) precisam se comunicar. As opções incluem: HTTP localhost, pipe nomeado, stdin/stdout subprocess, ou bindings JNA pra expor funções Java pro JS.

Decisão

Usar HTTP localhost via com.sun.net.httpserver.HttpServer (JDK nativo).

Formato:
  • Endpoint único: POST /api/invoke
  • Body: {"cmd": "nome", "args": {"chave": "valor"}}
  • Resposta: {"result": {...}} ou {"error": "..."}
  • Porta: escolhida pelo SO (porta 0), evitando conflitos
  • Escuta: 127.0.0.1 (só local, sem exposição externa)

Justificativa

  • Zero dependências: com.sun.net.httpserver vem no JDK 6+
  • Simplicidade: fetch padrão do JS, sem bibliotecas especiais
  • Debuggável: qualquer ferramenta HTTP (curl, Postman) pode testar
  • Separação clara: frontend e backend são independentes
  • Hot reload natural: servidor fica rodando, só recarregar a webview

Consequências

Positivas: Testável com curl, zero binding nativo, fácil de prototipar.
Negativas: Overhead de serialização JSON (marginal pra apps desktop). Latência de ~1ms por chamada.
