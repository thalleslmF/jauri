Jauri — Especificação Técnica

versão 0.5 • 2026-05-23 • ADRs

Resumo: Jauri é uma engine Java que executa apps desktop usando webview nativa (WebKitGTK) como frontend, comunicação via HTTP localhost, e compilação com GraalVM native-image. Concorrente de JCEF e JavaFX WebView — mais leve, mais rápido, só Linux.

Filosofia

  • Cada entrega é um binário executável e testável (não "80% do código")
  • Cada tarefa tem critério de aceite claro e testável
  • Cada milestone tem um teste E2E que verifica a integração completa
  • Mudanças estruturais viram ADRs (em HTML)
  • Não pular marcos — cada um resolve um problema real antes do próximo

Dependências: nenhuma • Entrega: binário que abre janela vazia • concluído

Bindings GTK via Panama FFM em libgtk-3.so + libgobject-2.0.so. Upcall stub para g_signal_connect_data. GtkMainLoop em thread separada.

Dependências: M1 • Entrega: webview carrega HTML que faz fetch pro backend Java • concluído

Servidor HTTP localhost com API JSON + static file server. JauriWebView vira backend. Frontend HTML/CSS/JS puro faz fetch pro backend e exibe resultado.

M3 ⏳ — Shutdown limpo + ciclo de vida

Dependências: M2 • Entrega: abrir/fechar o app sem leaks ou zumbis

M3.1 — Close handler no GTK (janela fechada)

gtk

Binding de callback g_signal_connect pra evento destroy da janela. Quando usuário fecha, disparar shutdown.

Critério: Fechar janela → HTTP server para, thread termina, processo sai (exit 0).

M3.2 — Graceful shutdown do HTTP server

http

HttpServer.stop(1) com timeout 1 segundo. Esperar requisições em andamento terminarem.

Critério: Matar app durante requisição lenta → servidor fecha sem socket preso.

M3.3 — JauriApp: classe de ciclo de vida

bridge

Criar JauriApp que orquestra: init(handlerRegistry) → start() → waitForClose() → stop(). Estado claro: CREATED → RUNNING → STOPPED.

Critério: Teste que chama start() + stop() sem abrir janela (sem GTK) completa em <1s.
E2E: xvfb-run mvn test -Djauri.e2e=true — teste abre app (janela + HTTP + WebView), verifica shutdown graceful via destroy signal, confirma exit 0 sem leaks.

M4 ⏳ — App Demo funcional

Dependências: M3 • Entrega: app de exemplo usando Jauri engine

Alvo: validar que a engine serve pra construir algo real. Um app de banco de dados simples com JDBC.

M4.1 — App: jauri-demo com tela de consulta SQLite

html bridge

Criar jauri-demo.jar com /static/index.html, campo de SQL, botão executar, tabela de resultados. Usar JDBC SQLite.

Critério: Rodar com Jauri → abrir janela → digitar SELECT 1 → ver resultado na tabela.

M4.2 — Hot reload durante desenvolvimento

html

Se JAURI_DEV=true, ao invés de extrair do jar, servir direto de src/main/resources/static/. Mudança no HTML reflete sem rebuild.

Critério: Alterar index.html → atualizar webview (F5 ou watch) → ver mudança.
E2E: xvfb-run mvn test -Djauri.e2e=true — teste verifica DB init, SELECT via frontend, resultado renderizado na tabela HTML.

M5 ⏳ — GraalVM Native Image

Dependências: M4 • Entrega: binário único de ~15MB que roda sem JDK

M5.1 — native-image com reflection config

graalvm

Criar reflect-config.json manual (HTTP server, Gson). Compilar o Jauri runtime como binário.

Critério: native-image -jar jauri.jar jauri → ./jauri abre o app demo.

M5.2 — Panama FFM + native-image

graalvm

Panama FFM precisa de --enable-native-access=jauri no native-image. Documentar as flags exatas para libgtk-3.so e libwebkit2gtk-4.1.so.

Critério: native-image compila sem warnings. Binário abre webview com HTML.

M5.3 — Reduzir tamanho do binário

graalvm

Analisar o que infla (reflection metadata, libs não usadas). Usar -H:+ReportUnusedElements. Alvo: <20MB.

Critério: ./jauri < 20MB. Demo SQLite roda.

M5.4 — Script de release: build + zip

graalvm

make release que compila native-image e gera jauri-linux-x64.zip com binário + README.

Critério: Rodar make release → .zip pronto pra distribuir.
E2E: xvfb-run ./jauri ... — binário nativo abre janela com WebView + HTTP + demo. Teste sem JDK instalado.

M6 ⏳ — Polimento + distribuição

Dependências: M5 • Entrega: ferramenta usável por terceiros

M6.1 — Tratamento de erros + logs

Logging com java.util.logging. Erros de Panama FFM viram exceções Java descritivas. stderr mostra stack trace, stdout fica limpo.

Critério: Se WebKitGTK não estiver instalado → mensagem clara: "libwebkit2gtk-4.1.so not found. Install: sudo apt install libwebkit2gtk-4.1-dev"

M6.2 — README + exemplos

Documentação: como criar um app Jauri, estrutura de diretórios, exemplos, FAQ.

Critério: Um dev novo consegue criar um app Jauri em 10 minutos seguindo o README.

M6.3 — Testes automatizados (headless)

Testes que não abrem janela: mockar Panama, testar HTTP server, testar handler registry, testar ciclo de vida.

Critério: mvn test roda 20+ testes em <10s sem GTK.
