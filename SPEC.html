Jauri — Especificação Técnica

versão 0.1 • 2026-05-16 • ADRs

Resumo: Jauri é uma engine Java que executa apps desktop usando webview nativa (WebKitGTK) como frontend, comunicação via HTTP localhost, e compilação com GraalVM native-image. Concorrente de JCEF e JavaFX WebView — mais leve, mais rápido, só Linux.

Filosofia

  • Cada entrega é um binário executável e testável (não "80% do código")
  • Cada tarefa tem critério de aceite claro e testável
  • Mudanças estruturais viram ADRs (em HTML)
  • Não pular marcos — cada um resolve um problema real antes do próximo

Marcos

M0 — Projeto Java + JNA + GTK Window

Dependências: nenhuma • Entrega: binário que abre janela vazia

Alvo de aprendizado: JNA, bindings GTK, Maven com native code.

M0.1 — Scaffold Maven com JNA

jna

Criar projeto Maven, adicionar JNA, configurar pom.xml, classe main, Makefile simples pra build + run.

Critério: mvn compile exec:java -Dexec.mainClass=jauri.Main roda sem erro e printa "Jauri OK"

M0.2 — JNA binding: libc (aquecimento)

jna

Criar interface jauri.jna.LibC com printf, getpid, sleep. Chamar do Java pra provar que JNA funciona.

Critério: LibC.INSTANCE.getpid() retorna um PID real. LibC.INSTANCE.printf printa no terminal.

M0.3 — JNA binding: GTK 3 mínimo

jna gtk

Interface jauri.jna.Gtk3 com: gtk_init, gtk_window_new, gtk_widget_show_all, gtk_main, gtk_main_quit. Chamar em main() pra abrir janela vazia.

Critério: Rodar Main.java → janela vazia aparece. Fechar com Ctrl+C ou botão X.

M0.4 — GtkMainLoop em thread separada

gtk jna

GTK precisa rodar na thread principal. Extrair loop pra classe GtkMainLoop que gerencia gtk_main() + shutdown via gtk_main_quit().

Critério: Fechar janela → gtk_main_quit é chamado → programa termina com exit code 0.

M1 — Janela com WebView carregando HTML

Dependências: M0 • Entrega: binário que abre janela com HTML renderizado

Alvo: binding WebKitGTK, carregar HTML inline, carregar HTML de arquivo.

M1.1 — JNA binding: WebKitGTK inicialização

jna gtk

Interface jauri.jna.WebKit com: webkit_web_view_new. Instanciar WebView, colocar dentro da janela GTK.

Critério: Janela abre com uma área vazia (a webview) dentro. 0 erros.

M1.2 — Carregar HTML inline na webview

jna html

Binding de webkit_web_view_load_html. Criar método JauriWebView.loadHtml(String html).

Critério: loadHtml("<h1>Jauri</h1>") renderiza "Jauri" na janela.

M1.3 — Carregar HTML de arquivo

jna html

Binding de webkit_web_view_load_uri com file://. Extrair assets de /static/ do classpath pra um diretório temp.

Critério: loadUri("file:///tmp/jauri-xyz/index.html") carrega HTML com CSS e JS inclusos.

M1.4 — WebView com resize automático

gtk jna

Configurar WebView pra ocupar 100% do espaço da janela com gtk_container_add e expand. A webview redimensiona junto com a janela.

Critério: Arrastar borda da janela → conteúdo HTML redimensiona proporcionalmente.

M2 — HTTP Server + IPC Bridge

Dependências: M1 • Entrega: webview carrega HTML que faz fetch pro backend Java

Alvo: servidor HTTP localhost, API JSON, frontend se comunicando com backend.

M2.1 — HttpServer simples na porta 0

http

Criar JauriHttpServer com com.sun.net.httpserver.HttpServer. Escutar em 127.0.0.1:0 (porta aleatória). Retornar a porta escolhida.

Critério: curl http://127.0.0.1:$PORT/health retorna {"status":"ok"}.

M2.2 — Servir arquivos estáticos

http html

Mapear / pra servir static/ do classpath ou diretório temp. Content-Type automático por extensão.

Critério: curl http://127.0.0.1:$PORT/index.html retorna o HTML servido.

M2.3 — Endpoint /api/invoke (POST JSON)

http bridge

Endpoint POST /api/invoke que recebe {"cmd":"ping","args":{}}, processa, retorna {"result":"pong"}. Usar Jackson/Gson pra parse.

Critério: curl -X POST -d '{"cmd":"ping","args":{}}' http://127.0.0.1:$PORT/api/invoke → {"result":"pong"}

M2.4 — HandlerRegistry: registrar comandos

bridge http

Criar HandlerRegistry que mapeia cmd string → função Java. Interface JauriHandler com handle(JsonObject args) → JsonObject.

Critério: registry.register("hello", args -> {"message": "Olá, " + args.get("name")}) funciona via api/invoke.

M2.5 — Integração: webview carrega da HTTP server

bridge html

Ao iniciar, extrair /static/ pra temp, subir HTTP server, abrir webview em http://127.0.0.1:$PORT/index.html. HTML faz fetch pra /api/invoke e exibe resultado.

Critério: App inicia → janela aparece com HTML renderizado → clicar botão chama Java → resultado aparece na tela.

M3 — Shutdown limpo + ciclo de vida

Dependências: M2 • Entrega: abrir/fechar o app sem leaks ou zumbis

M3.1 — Close handler no GTK (janela fechada)

gtk

Binding de callback g_signal_connect pra evento destroy da janela. Quando usuário fecha, disparar shutdown.

Critério: Fechar janela → HTTP server para, thread termina, processo sai (exit 0).

M3.2 — Graceful shutdown do HTTP server

http

HttpServer.stop(1) com timeout 1 segundo. Esperar requisições em andamento terminarem.

Critério: Matar app durante requisição lenta → servidor fecha sem socket preso.

M3.3 — JauriApp: classe de ciclo de vida

bridge

Criar JauriApp que orquestra: init(handlerRegistry) → start() → waitForClose() → stop(). Estado claro: CREATED → RUNNING → STOPPED.

Critério: Teste que chama start() + stop() sem abrir janela (sem GTK) completa em <1s.

M4 — App Demo funcional

Dependências: M3 • Entrega: app de exemplo usando Jauri engine

Alvo: validar que a engine serve pra construir algo real. Um app de banco de dados simples com JDBC.

M4.1 — App: jauri-demo com tela de login SQLite

html bridge

Criar jauri-demo.jar com /static/index.html, campo de SQL, botão executar, tabela de resultados. Usar JDBC SQLite.

Critério: Rodar com Jauri → abrir janela → digitar SELECT 1 → ver resultado na tabela.

M4.2 — Hot reload durante desenvolvimento

html

Se JAURE_DEV=true, ao invés de extrair do jar, servir direto de src/main/resources/static/. Mudança no HTML reflete sem rebuild.

Critério: Alterar index.html → atualizar webview (F5 ou watch) → ver mudança.

M5 — GraalVM Native Image

Dependências: M4 • Entrega: binário único de ~15MB que roda sem JDK

M5.1 — native-image com reflection config

graalvm

Criar reflect-config.json manual (JNA, HTTP server, Gson/Jackson). Compilar o Jauri runtime como binário.

Critério: native-image -jar jauri.jar jauri → ./jauri abre o app demo.

M5.2 — JNA + native-image (config especial)

graalvm jna

JNA precisa de jni-config.json e --initialize-at-build-time. Documentar as flags exatas.

Critério: native-image compila sem warnings JNA. Binário abre webview.

M5.3 — Reduzir tamanho do binário

graalvm

Analisar o que infla (reflection metadata, libs não usadas). Usar -H:+ReportUnusedElements. Alvo: <20MB.

Critério: ./jauri < 20MB. Demo SQLite roda.

M5.4 — Script de release: build + zip

graalvm

make release que compila native-image e gera jauri-linux-x64.zip com binário + README.

Critério: Rodar make release → .zip pronto pra distribuir.

M6 — Polimento + distribuição

Dependências: M5 • Entrega: ferramenta usável por terceiros

M6.1 — Tratamento de erros + logs

Logging com log4j ou java.util.logging. Erros de JNA viram exceções Java descritivas. stderr mostra stack trace, stdout fica limpo.

Critério: Se WebKitGTK não estiver instalado → mensagem clara: "libwebkit2gtk-4.1.so not found. Install: sudo apt install libwebkit2gtk-4.1-dev"

M6.2 — README + exemplos

Documentação: como criar um app Jauri, estrutura de diretórios, exemplos, FAQ.

Critério: Um dev novo consegue criar um app Jauri em 10 minutos seguindo o README.

M6.3 — Testes automatizados (headless)

Testes que não abrem janela: mockar JNA, testar HTTP server, testar handler registry, testar ciclo de vida.

Critério: mvn test roda 20+ testes em <10s sem GTK.
