Jauri — M0: Janela GTK com Panama FFM

versão 0.1 • 2026-05-18 • ADR-003 (Panama FFM)

Entrega do marco: Binário que abre uma janela GTK vazia e fecha limpo com exit code 0.
Stack: Java 22+ (Panama FFM) + GTK 3 + Maven + JUnit 5
TDD: Cada task tem teste unitário. O E2E cobre o deliverable completo.
Reuso: Bindings Panama de PanamaGtkBench.java adaptados para libgtk-3.so do sistema (não lib custom).

Tasks

M0.1 — Scaffold Maven + Panama FFM

panama

Criar projeto Maven com JDK 22+, pom.xml sem dependências externas, classe jauri.Main vazia.

Arquivos: pom.xml, src/main/java/jauri/Main.java

Critério: mvn compile gera class files sem erros. Main.main() printa "Jauri M0" e termina.

M0.2 — LibC binding (Panama warm-up)

panama unit

Criar jauri.native.LibC com Panama FFM para chamar getpid() (void→int) e printf() (string→void) de libc.so.6. Prova que o binding Panama FFM funciona com lib do sistema.

Reuso: Padrão Linker.downcallHandle + SymbolLookup.libraryLookup do benchmark PanamaGtkBench.java.

Critério: Teste unitário verifica: LibC.getpid() > 0. LibC.printf("hello") printa no stdout.

M0.3 — GTK 3 bindings (janela)

panama gtk unit

Criar jauri.native.Gtk3 com Panama FFM para libgtk-3.so:

  • gtk_init(String[] args) — inicializa GTK
  • gtk_window_new(int type) → ponteiro (long)
  • gtk_widget_show_all(long window)
  • gtk_main() — loop principal
  • gtk_main_quit() — sai do loop
  • g_signal_connect_data(long instance, String signal, long handler, ...)

Reuso: FunctionDescriptor patterns iguais ao benchmark, mas apontando pra libgtk-3.so via SymbolLookay.libraryLookup("libgtk-3.so", arena).

Critério: Teste unitário: Gtk3.gtk_window_new(GTK_WINDOW_TOPLEVEL) retorna ponteiro não-nulo. FunctionDescriptor são criados sem exceção.

M0.4 — GtkMainLoop lifecycle

gtk panama unit e2e

Criar jauri.GtkMainLoop que gerencia o ciclo de vida da janela GTK:

  • Estado: CREATED → RUNNING → STOPPED
  • start() — inicializa GTK, cria janela, registra callback destroy, entra em gtk_main()
  • stop() — chama gtk_main_quit()
  • waitForClose() — bloqueia até STOPPED

Callback destroy: Usar g_signal_connect_data com um callback MemoryLayout que chama stop() quando a janela é fechada.

Critério: Teste unitário verifica transição de estados sem GTK real. E2E xvfb-run abre janela → destroy → exit 0.

E2E Test — M0 Completo

M0 E2E: Janela abre e fecha limpo

e2e

Arquivo: src/test/java/jauri/M0EndToEndTest.java

Cobertura: M0.2 (binding libc) + M0.3 (binding GTK) + M0.4 (lifecycle)

Passos:

  1. Verificar que LibC.getpid() funciona
  2. Criar GtkMainLoop, chamar start()
  3. Aguardar 500ms para janela aparecer (xvfb-run)
  4. Chamar stop() simulando fechamento
  5. Verificar estado STOPPED e exit code 0
Critério: mvn test -Dtest=M0EndToEndTest passa com xvfb-run. Exit code 0. Janela não deixa processo zumbi.
